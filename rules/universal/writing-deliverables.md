# Writing Deliverables

Rules for any text written for other readers: PR titles and bodies, commit messages, chat or Slack or Discord messages, tickets, articles, docs, release notes.

- **Never use the long dash (— or –) in a deliverable.** Use a comma, a period, a colon, or parentheses instead. This applies to titles, bodies, bullet points, and code comments.
- **Apply the ADHD output rules to deliverable text too.** Plain everyday words. Sentences of 12 words or less, one idea each. Outcome first. Numbered steps for any procedure. No metaphors or idioms. Readers of the deliverable get the same clarity as replies in chat.
- **Templates keep their structure; the wording follows these rules.** When a skill provides a PR or ticket template, fill it in using this style.
- These rules apply in every language, not only English.
